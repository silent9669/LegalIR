### Required architecture

For each fold `f`:

1. Build hard-negative training pairs from fold-train queries only.
2. Train a fold-specific LoRA reranker.
3. Save to:
   ```text

   ```
4. Load that adapter.
5. Retrieve/rerank only fold validation queries.
6. Save fold candidate features and predictions.
7. Release fold model from VRAM before the next fold.

Pseudocode:

```python
for fold in folds:
    pairs = build_training_pairs(
        data_dir=data_dir,
        index_dir=index_dir,
        output_dir=fold_dir / "pairs",
        fold=fold.idx,
        use_all_queries=False,
    )

    adapter_dir = train_reranker(
        pairs_file=fold_dir / "pairs/reranker_pairs.parquet",
        config_path=...,
        output_dir=fold_dir / "reranker_adapter",
    )

    reranker = CrossEncoderReranker(
        model_name=BASE_RERANKER,
        adapter_path=adapter_dir,
        device=reranker_device,
    )

    evaluate_fold(...)
    del reranker
    gc.collect()
    torch.cuda.empty_cache()
```

# 6. P1 — Query Is Still Duplicated Inside Reranker Input

```text

```

inside the evidence pack.

`CrossEncoderReranker` then tokenizes:


This wastes a scarce 512-token context window and reduces available legal evidence.

### Required fix

```python
pair = (query, passage_without_question)
```

Use:

```python
evidence_builder.build(
    query,
    doc_id,
    candidate_record=candidate,
    include_question=False,
)
```

or change the dedicated reranker evidence API to guarantee the passage never includes `[QUESTION]`.

Training pairs and inference pairs must use the same representation.

### Required test

for production reranker examples.

- invalid function signature;
- pair file missing;

- fold training contains validation query IDs;
- final adapter is not loaded;
- final fusion model selected but not loaded;
- PyVi branch configured but not executed;
- BM25 metadata fields are all empty;
- parameter audit `>= 4B`;
- submission contains >5 IDs;
- submission query keys differ from public query keys;
- unknown corpus IDs are predicted;
- notebook smoke integration test fails;
- full OOF metrics are not produced;
- “trained” adapter has zero parameter delta.
